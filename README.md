# ANKA — Hearts of Iron IV mod editor

ANKA автоматизирует и упрощает работу с модами для Hearts of Iron IV: редактирование
стран, фокусов, событий, нац. духов, личностей, решений, динамических модификаторов и
локализации с автоматической генерацией нужных файлов и конвертацией графики.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
python main.py
```

> `tkinterdnd2` опционален: без него перетаскивание файлов из проводника отключается,
> но загрузка через диалог остаётся.

## Архитектура

Слоистая, SOLID-ориентированная. Зависимости направлены внутрь (UI → services → core/domain).

```
main.py                     точка входа
anka/
├── app.py                  контроллер приложения + навигация по экранам
├── config/                 константы (пути, размеры, языки), settings.json
├── core/                   инфраструктура, не зависящая от UI
│   ├── pdx/                парсер/сериализатор Paradox-скрипта (lark): grammar, nodes, parser, writer
│   ├── localisation/       чтение/запись .yml локализации
│   ├── images/             конвертация графики (jpg/png → tga/dds): converter, flags, icons
│   └── gfx.py              SpriteRegistry (запись спрайтов) + SpriteResolver (имя→файл)
├── domain/                 доменные модели (Mod, ModContext)
├── services/               сценарии: mod_repository, country/state/ideology/character/technology/trait
│   └── _fsutil.py          ensure_filename_case (регистр имён под ванилу)
├── editors/                редакторы-модули (плагины), регистрируются в реестре
│   ├── base.py             EditorModule (ABC) + EditorRegistry + EditorServices
│   ├── common/             переиспользуемые компоненты редакторов: диалоги (пикеры,
│   │                       предпросмотр PDX, галерея иконок), визуальный редактор
│   │                       скриптов (BlockTreeEditor + ScriptEditorDialog)
│   ├── countries/          редактор стран (флаги, цвета, названия, территория, политика, техи, персонажи)
│   ├── focuses/            редактор деревьев фокусов (canvas, инспектор, скрипты, диалоги)
│   ├── decisions/          редактор решений (дерево категорий, инспекторы, валидация)
│   ├── events/             редактор событий (неймспейсы, условные варианты, опции)
│   ├── ideas/              редактор идей / нац. духов (категории, создание с GUI-обвязкой)

│   ├── characters/         редактор «Личности» (создание персонажей всех ролей)
│   ├── effects/            каталог эффектов/триггеров/модификаторов игры (JSON + загрузчик)
│   └── _stubs.py           заглушки: dynamic_modifiers, localisation, ideologies, technologies, map

    ├── windows/            main_menu, settings, mod_list, mod_editor
    └── widgets/            ImageDropZone, ScrollableFrame, dnd (обёртка tkinterdnd2)
locales/                    переводы интерфейса (ru.json, en.json)
images/                     логотип и стандартные иконки приложения
```

### Принципы расширения
Новый редактор = подкласс `EditorModule`, зарегистрированный в реестре. Он получает
контекст мода (`ModContext`) и сам строит свой UI-таб. Ядро (парсер, конвертер, i18n,
темы) переиспользуется через сервисы — добавление функции не трогает существующий код.

### Редактор фокусов (`editors/focuses/`)
Полноценный canvas-редактор `common/national_focus`:
- **canvas.py** — сетка как в игре: иконки (DDS через `SpriteResolver`+Pillow, грузятся
  асинхронно пачками — открытие большого дерева не блокирует UI), линии prerequisite
  (пунктир = ИЛИ-группа), mutually exclusive, drag с привязкой к сетке (учитывая
  `relative_position_id`), zoom (Ctrl+колесо), панорамирование, сворачиваемая мини-карта.
- **inspector.py** — все свойства фокуса: id (переименование обновляет все ссылки и
  локализацию), название/описание по языкам, иконка (галерея всех `GFX_focus_*`/`GFX_goal_*`
  игры+DLC+мода или импорт своей картинки), позиция, cost, флаги, `search_filters`
  (значения сканируются из игры динамически), AND/OR-группы prerequisite, mutex
  (симметрично), 8 скриптовых блоков.
- **script_editor.py** — текстовый PDX-редактор с подсветкой, строгой валидацией парсером
  (битый скрипт не попадёт в файл) и браузером каталога эффектов/триггеров со вставкой
  сниппетов.
- **Shared/joint фокусы**: определения читаются по всем файлам мода+игры; ветки,
  подключённые к дереву через `shared_focus =`, рисуются рядом (read-only, если чужой файл).
- Ванильные деревья открываются read-only; «Копировать в мод» создаёт override-файл
  с точным именем. Валидация (дубликаты id, битые ссылки, циклы, коллизии клеток,
  отсутствующие иконки/локализация) — панель проблем с переходом по клику.

### Редактор решений (`editors/decisions/`)
Дерево «категория → решения» (мод + ванила read-only с «Копировать в мод»), инспекторы
решения и категории (иконки `GFX_decision_*` с галереей и импортом, cost/тайминги,
флаги, все скриптовые блоки через общий визуальный редактор — `allowed`/`visible`/
`available`/`target_trigger` только триггеры, `modifier`/`targeted_modifier` с
каталогом модификаторов), локализация по языкам, валидация (дубли id, категория без
определения, битые иконки, `selectable_mission` без таймаута...). Категория может
получать решения из нескольких файлов — редактор агрегирует их корректно; новые
решения попадают в файл мода, уже содержащий категорию, либо в `anka_decisions.txt`.
Общая архитектура с фокусами: block-backed модель (`services/decision_service.py`),
быстрый скан для списка (подсчёт глубины по скобкам — ванильные отступы ненадёжны),
`LocCatalog` (`services/_locutil.py`) для collision-safe локализации.

### Редактор событий (`editors/events/`)
Дерево «неймспейс → событие» (мод + ванила read-only с «Копировать в мод»; подпись
`id · [C/N/U/O/S] · заголовок`), полная форма для всех пяти видов событий
(`country_event`/`news_event`/`unit_leader_event`/`operative_leader_event`/
`state_event`; вид фиксируется при создании). Ключевые особенности:
- **Условные варианты** `title`/`desc`/`picture` — переиспользуемый
  `editors/common/variants.py` (`VariantListEditor`): упорядоченный список
  вариантов (▲/▼ — игра берёт первый с истинным триггером), простая
  (`title = key`) и условная (`title = { text = key trigger = {...} }`) формы
  конвертируются друг в друга автоматически; у picture внутренний ключ —
  `picture`, галерея спрайтов `GFX_report_event_*`/`GFX_news_event_*` по виду
  события + импорт своей картинки (DDS 355×140 в `gfx/event_pictures/` + спрайт
  в `anka_events.gfx`).
- **Опции** — список с ▲/▼ и drag&drop за ≡; под-форма выбранной опции: ключ
  name с автогенерацией `<id>.a..z`, локализованный текст, trigger/ai_chance,
  эффекты (визуальный редактор; известные ключи опции сохраняют позицию,
  неизвестные пары трактуются как эффекты и сохраняют порядок текста).
- id события = `неймспейс.N`; `next_id` сканирует ваниль+мод (коллизия с ванилью
  переопределила бы её событие); переименование переносит все производные
  loc-ключи (`.t*`, `.d*`, `.a..z`); новые события попадают в мод-файл, уже
  объявивший неймспейс, либо в `events/anka_events.txt` (с авто-`add_namespace`).
- Валидация: дубли id, id без точки, необъявленный неймспейс, событие без опций
  (не hidden), опция без name, отсутствующие локализация/картинка/спрайт,
  `mean_time_to_happen` при `is_triggered_only`, `major` у country_event —
  панель проблем с переходом к событию по клику.
- Модель block-backed (`services/event_service.py`), quick-scan подсчётом глубины
  скобок, `LocCatalog(vanilla_filter="event")`; `LocCatalog.rename_key` переносит
  произвольные ключи (обобщение `rename` решений).

### Редактор идей / нац. духов (`editors/ideas/`)
Дерево «категория → идея» (мод + ванила read-only с «Копировать в мод»). Категории в
дереве — это **ключи в файле** `ideas = { ... }`: имя категории (`country`,
`hidden_ideas`) либо имя слота (`economy`, `tank_manufacturer`, `political_advisor`…) —
у категории со слотами идеи группируются под слотами, а не под её именем. Одна категория
собирается аддитивно из многих файлов; подпись категории — `ключ · loc · [law/designer ·
N слотов]`. Инспектор идеи: id (переименование переносит loc-ключи `<id>`/`<id>_desc`,
если нет `name`-override), категория-combobox (перенос), название/описание по языкам,
`name`-override, иконка (`GFX_idea_*` галерея + импорт 63×50 DDS; пустой `picture` →
дефолт `GFX_idea_<id>`), `cost`/`removal_cost`/`level`/`ledger`, tri-state флаги
`default`/`cancel_if_invalid`, `traits` через MultiPick (trait_service), все скриптовые
блоки (`allowed`/`available`/… — триггеры; `on_add`/`on_remove` — эффекты;
`modifier`/`targeted_modifier` — с каталогом модификаторов; `equipment_bonus`/
`research_bonus`/`rule` — свободные блоки). Инспектор категории показывает определение из
`common/idea_tags` (read-only) и редактирует файловые флаги `law`/`designer`/
`use_list_view`.

**Создание категории** (`services/_ideagui.py`) — не только запись в `idea_tags`, но и
полная GUI-обвязка политического экрана: материализация пустых блоков под слот-ключами,
спрайты пустых слотов `GFX_idea_slot_<slot>` (копия ванильного DDS в мод), доп. кадр в
`gfx/interface/idea_categories.dds` (Pillow) с override-спрайтом `GFX_idea_categories`
(noOfFrames +1), расширение `max_slots.x` в мод-копии `countrypoliticsview.gui`. Ресурсы
накапливаются на собственных копиях мода; GUI-артефакты при удалении категории не
откатываются. Модель block-backed (`services/idea_service.py`), быстрый скан по подсчёту
скобок (quick==parse на всех 213 ванильных файлах, 6483 идеи), `LocCatalog(vanilla_filter
= "idea")`. Валидация: дубли id, неизвестный ключ категории, битые иконки/локализация,
слот закона без `default = yes`, `removal_cost = -1` при `cost > 0`, неизвестные трейты.

### Редактор боевых порядков — OOB (`editors/oob/`)
Наземные `history/units/*.txt` (файлы с `division_template`). Слева дерево «OOB-файл
(страна) → шаблоны дивизий» (мод + ванила read-only с «Копировать в мод»). Инспектор
шаблона повторяет игровой конструктор: **5×5** колонок основных полков (каждая — стек,
заполняется сверху) + колонка **поддержки** (до 5 рот, каждый тип максимум один раз).
Кнопки «＋» появляются только там, где добавление сохраняет форму, а удаляется только
нижняя рота колонки — движковый инвариант (проверен на всех 804 ванильных шаблонах, 0
нарушений): колонки примыкают слева, без вертикальных пропусков и **без «долин»** (полк не
короче одновременно левого и правого соседа — это и есть запрет «заполнено-пусто-заполнено»
в ряду). Тип полка/поддержки берётся из `common/units` (`sub_units`, `group = support` →
поддержка), наземные отфильтрованы от флота/авиации. Инспектор файла показывает
развёрнутые дивизии (имя/шаблон/локация, добавить/удалить/править) и **импорт шаблонов с
другой страны**. Модель block-backed (`services/oob_service.py`) хранит регименты как
колоночную модель `list[list[type]]` и сериализует обратно в `{ x y }`; `units={division…}`
и прочее сохраняются нетронутыми. Валидация: дубли имён, пустой шаблон, нарушение формы,
повтор поддержки, неизвестный юнит, ссылка дивизии на отсутствующий шаблон.

### Каталог эффектов и триггеров (`editors/effects/`)
Все эффекты (553) и триггеры (596) игры хранятся как данные: `effects.json` /
`triggers.json` (имя, скоупы, цели, описание, пример) загружаются при старте в
экземпляры `Effect`/`Trigger` через `ScriptCatalog` и переиспользуются любыми
редакторами (фокусы, события, решения...). Источник — **официальная документация
игры** (`<game>/documentation/*.md`), а не вики: она всегда соответствует установленной
версии. После обновления игры базы перегенерируются одной командой:
`python -m anka.editors.effects.generate`.

Все модули одного окна редактирования получают **один и тот же** `ModContext`.
Тяжёлые сервисы с кэшем (например `ModContext.characters`) объявлены как
`cached_property` на контексте — значит они общие для всех редакторов и кэш когерентен
(персонаж, созданный в «Личностях», сразу виден в «Странах» без повторного скана).

# Форматы файлов HOI4 (справка для разработчиков)

Всё содержимое мода — это набор файлов в дереве, повторяющем структуру игры. Игра
грузит **базовую игру + все DLC + все включённые моды**, накладывая их друг на друга
(см. «Правила переопределения»).

## 1. Paradox-скрипт (Clausewitz) — `.txt`, `.gfx`, `.gui`, `.mod`, `.asset`
Рекурсивный формат «ключ = значение», на нём написано почти всё, кроме локализации и карты.

```
key = value                 # скаляр (число, слово, дата 1936.1.1, yes/no)
key = "строка"              # строковое значение
key = { a b c }             # массив скаляров
block = {                   # вложенный блок
    inner = 1
    color = rgb { 10 20 30 }   # «тегированный» блок (rgb/hsv)
}
option = {...} option = {...}  # ключи МОГУТ повторяться
key >= 5   key < 3          # операторы сравнения (в триггерах)
@var = 20   x = @var        # скрипт-переменные
# комментарий до конца строки
```

Ключевые свойства (учтены в `anka/core/pdx/`):
- **Регистронезависимость ключей.** `spriteType` и `SpriteType` эквивалентны; в
  `_leader_portraits.gfx` доминирует именно строчный вариант. Резолвер спрайтов и
  чтение блоков сравнивают ключи без учёта регистра.
- **Повторяющиеся ключи** — норма (несколько `option`, `set_technology`, `recruit_character`).
  Модель хранит упорядоченный список, различает `get` (первый) и `get_all` (все).
- **Несбалансированные скобки** встречаются в ваниле — парсер имеет режим восстановления.
- **Кодировка: UTF-8 БЕЗ BOM.** Ведущий BOM ломает движок (`Unexpected token: ﻿…`).
  Пишется через `pdx.dump_file` (без BOM); читается через `utf-8-sig` (BOM снимается,
  если есть).

## 2. Локализация — `.yml` (псевдо-YAML, **не** настоящий YAML)
```
l_english:
 KEY:0 "Текст с $переменной$ и [ScopedLoc.GetName]"
 OTHER_KEY:1 "…"
```
- Первая строка — `l_<язык>:`. Каждая запись: ` KEY:<версия> "значение"` (ведущий пробел).
- **Кодировка: UTF-8 С BOM обязательно** — иначе игра молча не грузит файл
  (противоположность скриптам!). Пишется через `LocFile.save` (`utf-8-sig`).
- Один ключ должен встречаться один раз во всех загруженных файлах, иначе
  `loc key collisions` в логах.
- Язык также определяется суффиксом имени файла: `*_l_<язык>.yml` (например `countries_I_russian.yml`).

Важные ключи названий страны (см. `CountryService`):
`TAG`, `TAG_DEF` (полное), `TAG_ADJ` (прилагательное); варианты по идеологии —
`TAG_<ideology>` (+`_DEF`/`_ADJ`). Партии — в **отдельном** файле (`parties_l_*.yml`):
`TAG_<ideology>_party`, `_party_long`, `_party_desc`.

## 3. Изображения
| Что | Формат | Размеры | Куда |
|-----|--------|---------|------|
| Флаг страны | **TGA**, 32-бит, БЕЗ RLE | 82×52, 41×26 (`medium/`), 10×7 (`small/`) | `gfx/flags/[TAG].tga` (+ `_<ideology>` для косметических) |
| Иконка фокуса | **DDS** (ARGB8888 или DXT5) | ~100×88 | `gfx/interface/goals/` + спрайт в `interface/*.gfx` |
| Иконка идеи/духа | **DDS** | ~63×50 (large), 63×38 | `gfx/interface/ideas/` |
| Портрет лидера/командира | **DDS** | 156×210 (large) | `gfx/leaders/<TAG>/` |
| Портрет-иконка советника | **DDS** | ~65×67 (совпадает с `GFX_idea_*`) | `gfx/interface/ideas/` |
| Картинка события | **DDS** | 355×140 | `gfx/event_pictures/` |

- Любая графика в игре подключается **спрайтом** `SpriteType` из `interface/*.gfx`
  (имя `GFX_*` → `texturefile`). Путь текстуры — относительно корня того контента, где
  лежит `.gfx` (в DLC — относительно папки DLC). `core.gfx.SpriteResolver` собирает
  карту `имя → файл` по всем `interface/**/*.gfx` мода, игры и всех DLC.
- ANKA принимает от пользователя jpg/png/bmp/… и сама конвертирует/масштабирует в
  нужный TGA/DDS (`core.images`). Pillow ≥10 пишет и TGA, и DDS (несжатый ARGB8888 и DXT5)
  без внешних утилит.

## 4. Карта — `map/` (пиксельные форматы, **BMP**, не сжатые)
Все bmp имеют одинаковое разрешение с `provinces.bmp` (в ваниле 5632×2048), кроме
пониженных `trees.bmp` и `world_normal.bmp`.

| Файл | Формат | Назначение |
|------|--------|-----------|
| `provinces.bmp` | 24-бит RGB | каждая провинция = **уникальный** цвет; границы там, где цвета соприкасаются |
| `definition.csv` | CSV `;` | `id;r;g;b;type;coastal;terrain;continent` — связывает цвет с провинцией; `type` = land/sea/lake |
| `heightmap.bmp` | 8-бит grayscale | высота (0 — низ, 255 — верх; уровень моря ≈95) |
| `terrain.bmp` | 8-бит индексный | тип местности (палитра-индекс) |
| `rivers.bmp` | 8-бит индексный | реки, **толщина ровно 1px**, только ортогонально; спец-палитра (исток/слияние/направления) |
| `trees.bmp` | 8-бит индексный | плотность лесов (пониженное разрешение) |
| `cities.bmp` | 8-бит индексный | текстуры городов |
| `world_normal.bmp` | 24-бит | карта нормалей (обычно половинное разрешение) |
| `default.map` | PDX-скрипт | ссылки на файлы карты, диапазоны sea/lake провинций |
| `adjacencies.csv` | CSV `;` | особые связи: проливы, каналы (Суэц/Панама), непроходимость |

Провинции → штаты: `history/states/<id>-<Name>.txt` (`state = { id provinces={..} history={ owner=TAG } }`).
Штаты → стратегические/снабженческие регионы: `map/strategicregions/`, `map/supplyareas/`.

> Редактор карты в ANKA пока не реализован; форматы задокументированы для будущей работы.
> Для BMP критичны точная битность и **отсутствие сжатия** — иначе игра не читает файл.

## 6. Правила переопределения файлов (критично!)
Движок Clausewitz накладывает контент по относительному пути:
- **Аддитивные каталоги** (большинство `common/…`, `events/`, `history/countries/`,
  `history/states/`): грузятся файлы из игры И из мода; чтобы **переопределить** объект,
  дают файл с **тем же относительным путём** — тогда он замещает оригинал.
- **Сравнение пути — регистрозависимое** (даже на Windows). `SOV - Soviet Union.txt`
  НЕ переопределит ванильный `SOV - Soviet union.txt` — движок сочтёт их разными
  файлами. ANKA при записи зеркалит **точное** имя ванильного файла и авто-исправляет
  регистр на диске (`services/_fsutil.ensure_filename_case`).
- **Файлы-«заменители целиком»:** `common/countries/colors.txt` не сливается, а
  **полностью заменяет** ванильный. Поэтому цвет **новых** стран ANKA пишет в их
  файл-определение (`color = {..}` — игра берёт его как цвет по умолчанию), а `colors.txt`
  трогает только при перекраске **ванильной** страны и тогда засевает его всеми
  ванильными цветами.
- Порядок модов в плейсете тоже влияет на то, чей файл «побеждает» при коллизии.

## 7. Заметки о реализации / подводные камни
- **`Block.__bool__` всегда True.** Пустой блок иначе был бы falsy, и паттерн
  `parent.get_block(k) or Block()` молча отсоединял бы существующий пустой блок.
  Пустоту проверяйте через `len(block)` / `block.items`.
- **Общий кэш персонажей** (`ModContext.characters`) обновляется инкрементально
  (`create_or_update`/`delete`/`mark_recruited`) — полный скан только при первом
  обращении. Не возвращайте `refresh=True` без нужды.
- **Динамический парсинг:** идеологии, суб-идеологии, трейты, технологии, OOB и спрайты
  читаются из игры/мода на лету — хардкодить списки нельзя (моды их расширяют).
- **`tkinterdnd2` опционален** — код обязан деградировать до диалога выбора файла.
- **Настройки** и формы редакторов авто-сохраняются при уходе с экрана (`on_leave`);
  редакторы пишут только при реальных изменениях (флаг «dirty»), чтобы простой просмотр
  ванильной страны не создавал файлы мода.
